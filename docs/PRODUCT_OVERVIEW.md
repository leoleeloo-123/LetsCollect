# 产品概览

## 产品是什么

Let's Collect 是一个以 3D 数字收藏玩具为核心、优先服务手机端的收藏产品。

用户通过好友互动获得抽取券，使用抽取券遇见新的玩具，并逐步完成自己的系列收藏。产品的核心循环是：

```text
互动 -> 获得抽取券 -> 抽取 -> 收藏 -> 分享 -> 再次互动
```

完整的产品原则与边界见 `docs/PRODUCT_CONSTITUTION.md`。

## 四个一级模块

- 首页：本期系列、好友动态和互动获券任务；
- 抽取：抽取券余额、当前抽取池、抽取操作和结果揭晓；
- 收藏：拥有与未解锁玩具、系列进度和单只玩具检查；
- 好友：好友、申请、推荐和收藏关系概览。

`Explore` 的发现能力分散在首页、系列和收藏中，不作为一级入口。`Profile` 通过头像进入，不占用底部导航。

## 当前开发状态

`main` 当前已经是 React + Vite + TypeScript MVP，并由 Vercel Production 部署。

当前版本已经可以验证：

- 好友动态互动后获得抽取券；
- 消耗抽取券进行 Mock 抽取；
- 展示抽取揭晓结果；
- 将结果加入本地收藏；
- 筛选收藏并打开详情；
- 搜索、添加和接受好友；
- 将演示状态保存在浏览器本地；
- 通过可复用的 Three.js `ToyViewer` 查看当前激活的 GLB 玩具。
- 新抽取使用八种基础材质与五项工艺参数，旧 V1 果冻玉藏品保持原样。

静态 Legacy Hero 已迁入 `legacy/hero-prototype/`，继续作为视觉、材质和拖动检查行为的参考，不再是当前线上根入口。

## 当前不是正式能力

- 完整账户体系和生产级用户资料；
- 真实好友关系；
- 服务端抽取概率和结果；
- 权威的抽取券流水；
- 云端收藏数据；
- 支付、交易或真钱抽取。

## 近期目标

1. 根据真实手机体验持续调整四模块的信息架构；
2. 收敛视觉语言与交互反馈；
3. 继续验证 `ToyViewer` 在首页、收藏详情和抽取结果中的稳定性；
4. 收敛 Mock 数据合同，为云端收藏、好友和抽取服务做边界准备；
5. 在前端流程稳定后逐步替换为 Supabase 服务层。
