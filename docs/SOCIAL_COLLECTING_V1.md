# Social Collecting V1

状态：产品原型基线
日期：2026-07-17
范围：首页社区流、收藏家主页、轻量互动、图鉴与成就表达

## 1. 产品目标

Social Collecting V1 将 Let's Collect 从“可以抽取和查看 3D 玩偶的展示产品”推进为“以数字藏品为社交媒介的收藏社区”。

这一版本不追求功能数量。它需要让每一只玩偶同时具备四种价值：

- Collect：拥有、补全和发现；
- Show：策展、置顶和表达个人偏好；
- Compare：理解彼此收藏的共同点与差异；
- Interact：围绕具体藏品、图鉴和成就做轻量回应。

核心判断标准是：一个功能是否让收藏更有意义，而不是它是否增加了更多社交操作。

## 2. 核心循环

现有循环：

```text
互动 -> 获得抽取券 -> 抽取 -> 收藏
```

V1 目标循环：

```text
发现朋友的收藏时刻
-> 做出有语境的互动
-> 推进每日收藏仪式
-> 遇见新藏品
-> 策展自己的收藏身份
-> 获得认可
-> 再次发现与互动
```

社交行为必须引用一个明确对象：藏品、抽取结果、图鉴、成就或展柜更新。V1 不提供无对象的通用发帖。

## 3. 体验原则

1. 3D 玩偶始终是最高视觉焦点；列表使用缓存缩略图。
2. 保留首页、抽取、收藏、好友四个一级入口。
3. 首页不是无限信息流，而是每天可读完的收藏简报。
4. 收藏页承担个人身份，不新增一级 Profile 页面。
5. 互动以预设反应和短鼓励为主，不建设私信或聊天。
6. 奖励有每日上限，避免点赞、评论和访问变成刷券行为。
7. 排名优先使用好友范围、主题范围和周周期，不做永久总财富榜。
8. 同一页面只加载一个活跃 GLB，其他藏品使用缩略图。

## 4. 信息架构

### 首页：今天的收藏时刻

首页回答三个问题：

- 今天朋友中发生了什么值得看的事？
- 我还差什么可以完成今日收藏仪式？
- 我接下来要欣赏、互动还是抽取？

首屏由一个社区焦点事件和一只活跃 3D 玩偶构成。其后依次是每日仪式、社区动态和本周主题入口。

首页事件类型：

- `draw_revealed`：获得高稀有度藏品；
- `set_completed`：完成图鉴或系列；
- `achievement_unlocked`：解锁收藏成就；
- `showcase_updated`：更新代表藏品或置顶展柜；
- `collector_milestone`：达到收藏里程碑。

V1 反应词围绕收藏语境：想要、好闪、欧气、同款。一次事件对一个用户只记录一个主反应。

### 收藏：收藏家主页

收藏页回答三个问题：

- 我是怎样的收藏家？
- 我最想展示哪些藏品和成就？
- 我拥有什么，还缺少什么？

页面顺序：

1. 收藏家身份：头像、昵称、称号、加入时间和简短描述；
2. 我的展柜：一件代表藏品、三件置顶藏品；
3. 图鉴进度：按动物与按材质形成两套正交图鉴；
4. 展示成就：最多展示三枚；
5. 完整收藏网格与现有筛选；
6. 单只藏品详情与 3D 检查。

收藏称号优先由拥有结构推导，例如“水晶动物收藏家”或“独角兽全材质”。V1 不要求用户填写复杂档案。

### 好友：共同收藏与比较

好友页继续负责关系管理，后续增加：

- 共同拥有；
- 只有我拥有；
- 只有好友拥有；
- 图鉴完成度比较；
- 好友范围的本周收藏亮点。

V1 原型不新增全局关注系统。

## 5. 图鉴策略

现有 6 种造型和 8 种材质可以同时组成两种图鉴，无需增加 GLB：

- 造型图鉴：同一动物的 8 种材质，例如“独角兽全材质”；
- 材质图鉴：同一材质的 6 种动物，例如“水晶动物”。

进度必须从用户实际拥有的 `Collectible` 推导，不保存可被单独修改的完成百分比。

## 6. 成就与奖励

首批成就：

- 初次相遇：拥有第一件藏品；
- 材质学徒：拥有四种不同材质；
- 完整图鉴：完成任意一套造型或材质图鉴；
- 神话时刻：拥有第一件神话藏品；
- 被看见：一次收藏时刻获得指定数量反应。

徽章本身是可展示对象。成就解锁应提供一次清晰、短暂的反馈，不依赖持续粒子或大面积特效。

抽取券奖励来自有限的每日仪式：

- 欣赏不同朋友的收藏时刻；
- 对不同事件做出有语境的互动；
- 查看一次图鉴缺口；
- 完成一个新的收藏里程碑。

所有正式奖励必须写入 `TicketTransaction`，且服务端具备幂等约束。分享、重复访问和无限评论不直接发券。

## 7. 领域模型

现有对象继续保留：`User`、`Collectible`、`Series`、`Friendship`、`DrawResult`、`TicketTransaction`。

建议增加：

```text
CollectorProfile
CollectionShowcase
CollectionSetDefinition
ActivityEvent
ActivityReaction
AchievementDefinition
UserAchievement
MissionDefinition
MissionProgress
```

约束：

- `ActivityEvent` 是服务端产生的结构化事件，不是万能帖子；
- `ActivityReaction` 唯一键为 `(event_id, user_id)`；
- 图鉴进度由藏品所有权派生；
- 成就解锁只追加，不由客户端直接提交；
- 排名是可重建快照，不是资产权威来源；
- 展柜只引用用户已拥有的藏品。

## 8. Mock 原型范围

第一轮直接验证两个页面：

### 新首页社区流

- 社区焦点事件与单一 3D 主视觉；
- 每日互动仪式及现有领券状态；
- 三种结构化动态卡片；
- 有语境的反应按钮；
- 本周主题与好友范围提示。

### 收藏家主页

- 收藏家身份和派生称号；
- 一件代表藏品与三件置顶藏品；
- “水晶动物”和“独角兽全材质”进度；
- 三枚展示成就；
- 保留现有四列收藏网格、筛选和详情抽屉。

原型继续使用本地 Mock 状态，不提前创建 Supabase 表。

## 9. 验收标准

### 首页

- 用户在首屏能识别“谁发生了什么收藏事件”；
- 首屏只有一个主要 3D 焦点和一个主要操作；
- 完成互动后，进度与领券状态同步更新；
- 手机页面不依赖横向滚动；
- 动态列表不加载多个 WebGL Canvas。

### 收藏页

- 页面首先表达收藏家身份，而不是首先出现筛选器；
- 代表藏品使用一个活跃 3D 查看器；
- 图鉴进度由当前收藏实时推导；
- 置顶藏品和完整网格均可打开同一个详情抽屉；
- 320px 宽度仍保持四列网格可读；
- 桌面与手机都没有文本遮挡或布局跳动。

## 10. 后续顺序

5. 接入 Auth、RLS 和云端 repository；
